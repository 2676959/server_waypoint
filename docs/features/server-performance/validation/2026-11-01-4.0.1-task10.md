retain the direct-player and execute-as local-teleport feedback failures seen
in [4.0.0](2026-10-31-task10-storage-commands.md). The teleports reach the expected
world and x/y/z; the success feedback required by those assertions is not
observed by the player client. All four storage cases PASS. Every medium timing
window meets the absolute native tick budgets.

Six selected Paper 1.21.11 cases completed three fresh-process repetitions each:
**18 complete measurement / exact save-reopen windows**. These are published
4.0.1 bytes, not a build of current development sources. The
[machine-readable evidence](2026-11-01-4.0.1-task10-evidence.json) retains per-run
identities, metrics, assertions and raw attempt paths.

## Decoder follow-up

The two local-TP feedback FAILs above do not establish a 4.0.1 bug. The
published confirmation is valid system chat. Its root carries style and `extra`
without a `text` field, and the player head is an object component identified
by a `player` profile rather than an `object` type tag. Azalea 0.15.1 rejected
that component, so the bot dropped the packet before recording chat. Plain text
in the same message decoded.

The performance bot now vendors a patched `azalea-chat` that accepts this wire
shape and renders the head with Minecraft's description, `[unknown player head]`
when the profile has no name. A functional small-behavior rerun on published
4.0.1, root `/Volumes/ssd/sw-task10-object-decoder-20261101b`, reports
`Task 10 native behavior PASS; exact save/reopen PASS`. The direct command's
observed chat is `✔ Teleported [unknown player head] swp_reader_00 to [P] alpha`,
and the execute-as assertion passes with it. Bot SHA-256 for that rerun is
`f39dbf5ce6ce70557be3745ebb5fd75900cb6a21369379db49729c02fa843125`. The sealed
timing repetitions in the table above were collected with the previous decoder.
A later remasurement with the patched decoder is
[2026-11-01-4.0.1-task10-decoder.md](2026-11-01-4.0.1-task10-decoder.md).
