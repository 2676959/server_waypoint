## Second review

The final review deferred ten minor findings. Each was resolved in its own commit, with a test that
failed first unless noted:

1. **Focus on a hidden row widget:** after every relayout and every focus request, the screen
   reveals a focused row widget that ended up hidden, such as the Sync button that closing its
   dialog refocuses after a longer status shrank the list. Focus leaves the widget only if its row
   can't be shown. `ClientConfigScreenFocusTest`.
2. **Inactive reset icons:** an inactive `IconButton` tints its icon with `TEXT_DISABLED`.
   `WidgetThemeStateTest` covers the tint. The look was chosen over a dimming overlay and a hidden
   icon from computed previews of all three built-in themes over dark, sky and white worlds; the
   Themes check below still has to confirm it in game.
3. **Composite row controls:** a row owns every widget its control visits, and is a Tab stop while
   one of them is active. `SettingsListWidgetTest`.
4. **Build targets:** the 16 targets never compiled before all compile, as listed above.
5. **Translation placeholders:** `ClientConfigTranslationTest` compares the arguments each string
   fills in, so `%1$s` counts like `%s`, and a literal `%%` doesn't count. Removing the `%1$s` from
   the Spanish title made the new test fail and left the old one passing.
6. **Tab wrap-around:** before vanilla handles Tab, `SettingsListWidget.revealTabTarget` scrolls the
   next stop into view when it's a hidden row widget. Tab from Done wraps to the first row, and
   Shift-Tab from the footer reaches the last row. `SettingsListWidgetTabTest`.
7. **Pausing:** the settings screen and its theme editor pause exactly when their parent screen
   does, so opening them from the pause menu's mod list keeps singleplayer paused.
   `MovementAllowedScreenPauseTest`.
8. **Duplication:** `TranslucentButton.fitted`, `DrawContextHelper.NO_MOUSE` and public
   `VisualPositioning` getters replace the copies. `TranslucentButtonTest` and
   `VisualPositioningTest`.
9. **Sync failure log:** a failed sync logs the mod's display name. No unit test: the screen can't be
   built without the game, and the line only feeds the log.
10. **Test doubles:** `IntegerSlider`'s protected constructor takes the number field, so
    `IntegerSliderTest` and `MovementAllowedScreenPopupEscapeTest` no longer set private fields by
    name.

## Follow-ups

Problems found while resolving the second review, each fixed in its own commit:

1. **Resize with a dialog open:** from 1.20.5, vanilla moves focus to the next Tab stop after every
   rebuild when the keyboard was used last, which took it from a dialog's Cancel button to its
   confirm button, so Enter confirmed. `MovementAllowedScreen` now skips that while
   `hasOpenModal()` reports an open modal. `MovementAllowedScreenInitialFocusTest`. The tests
   compile on both sides of the 1.20.5 branch, on 1.20.1, 1.20.4 and 1.20.6 Fabric, and all 39
   targets compile with the change.
2. **Combo-box test double:** `MovementAllowedScreenPopupEscapeTest` set `ComboBoxWidget`'s private
   `input` field by name. It now uses a `ComboBoxWidget` subclass that reports no suggestions open,
   and `ComboBoxWidget` is no longer `final`. A real combo box can't take focus in a unit test from
   26.1, because its editable text field asks the game to start text input, so the test no longer
   checks the inner field's focus. Removing the combo-box case from `dismissFocusedInput()` makes
   it fail.

## Known behavior

On servers where VoxelMap asks the player to choose a world, a sync before that choice goes to
VoxelMap's current world, as auto sync already does. The non-English strings are drafts that need
a native speaker's review before release. A composite row control's partly visible widgets
disappear instead of being drawn clipped; no row uses one yet.
