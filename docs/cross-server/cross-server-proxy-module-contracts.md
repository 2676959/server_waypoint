# Cross-server proxy module contracts (step 3)

This step adds module boundaries, dependency packaging, and test fixtures. It does not implement
catalogs, coordination, a wire codec, backend connections, permissions policy, pairing, or player
transfers. The Velocity entrypoint logs initialization/shutdown and registers no listener socket,
command, plugin-message channel, scheduled worker, or connection service.

## Ownership and APIs

| Module | API | Contract |
| --- | --- | --- |
| `common` | `TransportLifecycle` | Nonblocking, idempotent start/stop with stable `TransportResult` outcomes. The owner serializes lifecycle and crypto work; shutdown completion includes resource cleanup. |
| `common` | `BackendTransport` | Outbound lifecycle for an explicitly configured `RemoteServerId`. |
| `common` | `CoordinatorTransport` | Listener lifecycle and per-ID session disconnect. Disconnect alone does not revoke an ID; registry policy must prevent re-admission. |
| `proxy-common` | `ProxyPlayerRouter<S>` / `TransferAdapter<S>` | Lookup by proxy-authenticated UUID and asynchronous switch request to opaque adapter-owned destination `S`, with an expected source ID checked immediately before switching. |
| `proxy-common` | `ProxyPlayerSnapshot` | Immutable point-in-time UUID/current-server observation. It is not a forwarded player claim or authorization for a later switch. |
| `proxy-common` | `ProxyServerDirectory<S>` | Exact configured stable server-ID mapping to an opaque adapter handle. No hostname or display-name inference. |
| `proxy-common` | `ProxyPermissionChecker` | Current proxy permission lookup, denying unknown/offline players. Coordinator and destination policy remain later work. |
| `proxy-common` | `ProxyLifecycle` | Startup/shutdown/disconnect callbacks and one-shot nonnegative-delay scheduling with idempotently cancellable registrations. Zero delay queues work rather than executing inline. |
| `proxy-common` | `TransferResult` | Success, offline player, changed source, unknown destination, denied permission, failed connection, or cancellation. Success denotes a server switch, never a completed destination teleport. |
| `velocity` | `ServerWaypointVelocity` | Inert plugin lifecycle entrypoint. Real Velocity adapter behavior belongs to step 16. |

Shared APIs contain no Velocity, Bukkit, Minecraft, or BungeeCord types. `S` is chosen by each
adapter, so a future proxy adapter can implement the same contracts without changing policy types.
Expected operation failures use result values; callers must not depend on platform exceptions.
No production fake implementation is shipped: the in-memory adapters live only in `proxy-common` tests.

The 11 contract tests cover exact registration, stale handles, asynchronous completion, source
changes after lookup, disconnect, permission revocation, failed connections, cancellation on
shutdown, callback ownership, and backend/coordinator lifecycle and admission fixtures. These
fixtures exercise the abstraction; they do not implement or prove production authorization or transport.

## Build and runtime choices

`common` and `proxy-common` use Java 17. The Velocity 4.1.1 API currently requires Java 25;
`velocity` therefore uses a Java 25 toolchain/runtime target with Java 17 source language syntax.
Its API and annotation processor are compile-only/build-time dependencies, not shaded libraries.
`velocity-plugin.json` is generated by the Velocity annotation processor, using `ModInfo.MOD_VERSION`.

The Velocity artifact is `velocity/build/libs/server_waypoint-3.1.0-velocity.jar`. It is built by
`build` but is not added to existing Modrinth/CurseForge upload tasks or the 38-artifact backend release
collector. The unshaded diagnostic JAR is not deployable. Release wiring for Velocity remains later work.

Noise is an `implementation` dependency of `common`, pinned by `noise_version=0.1.1`. Every platform
explicitly retains it in its final shading route. `gradle/noise-packaging.gradle.kts` checks the
reviewed JAR SHA-256 before packaging and includes its MIT notice. All platforms use the private
`_959.server_waypoint.internal.noisekk` namespace. Step 3 did not call Noise at runtime; the shared [step-6 channels](cross-server-tcp-transport-v1.md)
now do, without enabling platform lifecycle startup.

Forge requires an additional packaging boundary: `shadedJar` reads the finished `shadowJar`, and
`shadedJarJar` adds jar-in-jar dependencies to that relocated input. Older targets then reobfuscate
the result. Replaying the Shadow task's raw CopySpec would reintroduce original Noise classes and
could choose unrelocated caller bytecode; the old route was replaced rather than filtering only
one visible symptom. Existing final artifact names and release selection are preserved.

## Validation

See [platform verification](cross-server-step3-validation.md) for exact targets, commands,
artifact hashes, native classloader evidence, and any remaining startup blockers.
The [test tools](../../tools/noise-platform-test/README.md) remain outside release source sets.

```sh
./gradlew :common:test :proxy-common:build :velocity:build --max-workers=2 --console=plain
./gradlew build --max-workers=2 --console=plain
```

No active Stonecutter project switch is needed. Model/codec work was subsequently completed in steps 4 and 5;
production transport must not bypass unresolved platform verification gates.
